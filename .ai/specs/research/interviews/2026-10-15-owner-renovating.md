## Follow-up 3, same day (owner's answers)

- Second-hand (owner reporting a conversation): the owner talked to a friend about the idea; the friend(s) said they have the same problem and want to use the app for testing. Number of friends and their own words were not captured.
- Decision (stated): a task can be made of subtasks, e.g. a decorative wall: a) priming, b) decorative plaster, c) impregnation, d) TV mount; every step has a cost.
- Decision (stated): first, the user fills in subtasks and their costs; later, AI may estimate cost for subtasks and tasks.
- Decision (stated): assessment of the amount of work is a feature for the next version; for now the user can add their own assumptions about effort.

## Follow-up 4, same day (owner's answers)

- Decision (stated): effort is recorded as a simple level.

Amounts were not calculated; the owner says they are hard to calculate but real, in products, water and repeated preparation.

- Decision (stated): do not store money to spend; just show the task cost.

- Requested feature (stated): a task can be assigned to several rooms or spaces at once, e.g. curtain rod installation to the bathroom, living room, dining room and so on.
- Not stated: whether "important" and "urgent" are two markers or one; how a cost becomes "spent" (e.g. when a task is done or when money is paid).

## Follow-up 16, refresh session, 2026-10-16 (owner's decisions)

- Decision (stated): some features move to version 2; the first prototype should be simple and for the owner.
- Decision (stated): a task's estimated cost is typed by the user, not counted from subtasks and not AI-estimated. A task has a description.
- Decision (stated): a task can still have subtasks; a subtask is a small task inside a task and can also have an estimate. A subtask estimate changes nothing in the main task; the user keeps subtask costs in mind when filling in the main task's estimate.
- Decision (stated): inputting real cost is removed from version 1; the real-cost model needs refining.
- Decision (stated): "spent" and "spend" are misleading. New names: future expenses, incurred expenses, and a separate category for expenses of completed tasks.
- Decision (stated): the version 1 summary counts only future expenses: the estimated values of main tasks typed by the user; subtask estimates are not counted.
- Decision (stated): a task can be marked completed; marking a main task completes its subtasks. First said to change only status; see the next answer.
- Stated (answers to the agent's questions the same day): a completed task drops out of future expenses, because its expenses have been incurred. Expenses of completed tasks must not be a range, so the task's estimate cannot be counted into that category. The typed estimate stays a min–max range and so does future expenses. Incurred expenses is reserved for version 2.
