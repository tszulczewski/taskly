# Lessons Learned

Long-term memory for AI agents working on this project. Read this file **before starting any task**.

## How to use

- Add a one-line entry to the index below for every lesson. Newest first.
- Put details (context, root cause, fix, how to avoid) in `.ai/lessons/YYYY-MM-DD-slug.md`.
- Small, self-explanatory lessons may live only in the index.
- Before adding, check for an existing lesson on the topic; update it instead of duplicating.
- Remove or correct lessons that turn out to be wrong.

## Index

- 2026-10-30 — Subtask UI on TanStack Query 5: per-call `mutateAsync(vars, { onSuccess })` callbacks fire only for the observer's **last** call (one `#mutateOptions` per observer), and `mutation.context` lags a render and holds only the latest mutation. So per-call state such as "the list before this add" goes in the caller's closure, not in those callbacks. A server answer that replaces a parent row (the parent `TaskView` for a subtask add, edit or delete) must keep that row's other pending subtasks, or one add's answer drops another add's temporary subtask (`putTask` in `use-tasks.ts`). The edit form of a task with subtasks hides the amount fields, but it still validates and submits their values: prefill them empty, not with the formatted sum. A sum above the typed-amount cap would otherwise fail validation on a field nobody can see and block the save, and the update must skip `estimate` for such a task anyway (409).
- 2026-10-30 — Pausing services on row locks (subtask races): a `FOR KEY SHARE` request is granted even while a `FOR UPDATE` waits on the same row behind another `FOR KEY SHARE` holder, so a key-share holder stops an estimate edit while a subtask insert passes it. To stop a service right after an explicit row lock and before its insert's FK check, have a holder insert an uncommitted row at the same unique key, then `tx.rollback()`. A `FOR UPDATE` waiter on a multixact shows only the first locker in `pg_blocking_pids` → [details](lessons/2026-10-16-cross-actor-list-locks.md)
- 2026-10-30 — `next dev` runs in `packages/app` and reads `.env` only from there, so the repo-root dev `.env` was never loaded and every page failed env validation (`ZodError`, all variables `undefined`). `next.config.ts` now calls `process.loadEnvFile` on the root `.env` in `PHASE_DEVELOPMENT_SERVER` only (already-set variables win; builds and the standalone server keep getting env from CI/systemd). Don't use `@next/env` `loadEnvConfig` for this: Next has already called it for the app dir and the cached result makes a second call a no-op. A smoke check of the standalone build does not exercise `next dev`.
- 2026-10-29 — agent-browser readouts for assertions: `--json cookies get` lists only the cookies of the current page (empty on `about:blank`), HttpOnly included; a cookie set with `cookies set` and no `--expires` reports `expires: -1`, a renewed one its expiry in epoch seconds. `--json network requests --filter <substr>` lists the page's fetches with `method`, `--clear` resets the log; prove a "no request was sent" check with a positive control (one request after a valid submit). To check state between a page render and the client fetch that follows it, `network route <glob> --abort` the API before `open`, check, then `unroute` and retry from the UI (`test/tasks-browser.integration.test.ts`, renewal). A DS `Input` with a `suffix` ("zł") adds the suffix to its `aria-describedby`, and a `FormField` with `optionalText=""` leaves a trailing space in the label's `textContent`; read a field's message by FormField's `<input id>-error` and trim labels.
- 2026-10-29 — Screen tests for amounts with NBSP: Testing Library string matchers (`getByText("1 500 zł")`) collapse whitespace in the DOM text but not in the expected string, so an expected string with U+00A0 never matches; compare `textContent` of the element (e.g. `[data-slot="estimate-range"]`). TanStack Query 5: refetching a query that failed before it ever had data resets it to `status: "pending"` (error cleared), so `isError` is false during the retry and a list shows its skeleton instead of "Trying again…"; keep a local `retrying` flag (`TaskListScreen`). Query notifications are scheduled with `setTimeout`, so `await act(async () => resolveFetch())` does not show the result yet; use `findBy…`/`waitFor`. Manual smoke on the standalone build with the dev `.env`: its empty `ANTHROPIC_API_KEY` fails env validation and every page shows "This page couldn’t load"; pass a placeholder (`ANTHROPIC_API_KEY=test-key-not-used`).
- 2026-10-29 — TanStack Query 5 with concurrent task mutations: restoring the `onMutate` snapshot on error also drops other adds' pending rows (and undoes results written in between), so a failed add removes only its own temporary row. Each settle's `invalidateQueries` refetch replaces the list and wipes rows still pending, so skip it while `queryClient.isMutating({ mutationKey }) > 1` (the settling mutation still counts as pending in `onSettled`); then no invalidation cancels an older in-flight refetch, so `cancelQueries` before writing a server result, or the stale answer lands on top. `MutationCache`/`QueryCache` `onError` runs before the hook's own `onError` (the 401 redirect lives there, `lib/query-client.ts`). In tests, `useMutation`'s `result.current.context` lags `mutateAsync` by a render: read it in `waitFor`; and the `react-hooks/globals` lint rule rejects assigning an outer variable inside a test component, so hand the value out through a `useEffect` callback.
- 2026-10-29 — Route Handlers with `apiHandler`: annotate only the context parameter (`async (req, ctx: RouteContext<"/api/tasks/[taskId]">) => …`); writing `apiHandler<Ctx>(…)` sets `T` to its default `unknown` (TypeScript has no partial type-argument inference), so the result is no longer typed by the response schema. Read bodies with `readJson(req)` (`lib/api.ts`): a bare `req.json()` on a malformed or empty body throws `SyntaxError`, which `mapError` turns into a 500. Better Auth's renewed session cookie, set by `nextCookies()` through `cookies()`, is merged by Next 16 into the `Response.json` a handler returns, so `requireUser` renews cookie and DB row together (`test/tasks-http.integration.test.ts`).
- 2026-10-29 — Zod 4 (4.6): a key typed `z.unknown()` (or `z.any()`) is required at runtime, so `z.object({ ok: z.literal(true), data: z.unknown() })` rejects `{ ok: true }`, which is what `Response.json({ ok: true, data: undefined })` sends for a handler that returns nothing; use `z.unknown().optional()` (`apiResponseSchema`). Also: a Zod schema typed with a union of schemas (an `it.each` table mixing `taskViewSchema` and `taskListResponseSchema`) does not match a structural `ResponseSchema<T>` parameter; widen it to `ResponseSchema<unknown>` in the test.
- 2026-10-29 — Unit-test a service's SQL with a real drizzle `Db` over a fake pg client: `drizzle({ client: { query: async (config, params) => ({ rows }) } as unknown as Pool, schema })` records the exact SQL text and params (lock clauses, `COLLATE "C"`, insert columns), and a rejected `query` arrives wrapped in a real `DrizzleQueryError` (pg error in `.cause`). A non-Pool client runs `begin`/`commit`/`rollback` as plain `query` calls on it; rows of a `select`/`returning` with fields come back in array mode, so reply with arrays in select-key order (`tasks.test.ts`). In barriers, `pg_blocking_pids` also counts a "soft block" (a waiter ahead in the same lock queue), so "A is blocked by B" can hold while B holds nothing A needs → [details](lessons/2026-10-16-cross-actor-list-locks.md)
- 2026-10-29 — `INSERT … ON CONFLICT` on a partial unique index (e.g. `lists_default_for_user_kind_uq … WHERE default_for_user_id IS NOT NULL`) must repeat the index predicate, or PostgreSQL finds no matching constraint and every insert errors; in drizzle 0.45 pass it as `onConflictDoNothing({ target: [...], where: isNotNull(col) })` (renders `on conflict (…) where … do nothing`; check with `drizzle.mock().toSQL()`). To test the conflict path deterministically, hold the conflicting row in an open transaction, wait in `pg_stat_activity` for `wait_event_type = 'Lock'`, then commit; release that transaction in a `finally`, or a failing assertion leaves it open and `afterAll` cleanup hangs until the hook timeout.
- 2026-10-29 — Zod 4 (4.6): an object `.refine` still runs when a field failed a non-type check (e.g. `.max`), so one input can give both the field error and the refine error; check fields first when each error must land on one form field (`estimateFromAmounts`). A `.partial()` object keeps a key sent as `undefined` in its output, so an "at least one field" refine must test values (`Object.values(v).some((x) => x !== undefined)`), not `Object.keys`. Also: `\u00a0`-style escapes written by an agent (Write tool or heredoc) can land in the file as literal invisible characters; check with `grep -nP '[\x{a0}\x{202f}]'` and convert them back to escapes.
- 2026-10-29 — drizzle-kit: `npm run db:generate -- --name x` loses `--name` (npm takes it as its own config); run `npm run generate -w @taskly/db -- --name=x`. Run drizzle-kit only through the `@taskly/db` scripts: from the repo root with `--config packages/db/drizzle.config.ts` its `out: ./migrations` resolves against the cwd and writes a stray root `migrations/` folder. In an ALTER migration it emits FKs before `ADD CONSTRAINT … UNIQUE`, so a composite FK onto a new unique needs the two statements swapped by hand before first apply (the snapshot is unaffected).
- 2026-10-29 — agent-browser in a sandboxed session fails with `Failed to create socket directory: Permission denied (os error 13)` (it uses `XDG_RUNTIME_DIR`). Set `AGENT_BROWSER_SOCKET_DIR` to a short writable directory (e.g. `/tmp/claude-1000/ab`, mode 700); the long scratchpad path fails with "Socket path would be 118 bytes (max 103)".
- 2026-10-29 — A raw-mode password prompt must reject, not drop or discard, every control key except Enter, Backspace, Ctrl+C and Ctrl+D. Dropping only ESC turned Left (`ESC [ D`) into password text `[D`. Discarding whole sequences is also wrong: `abc` + Left + `X` would store `abcX` while the user meant `abXc`, and repeating it passes the confirmation check, which locks the user out. Rejecting on ESC itself (plus C1 `\x80`–`\x9f` for 8-bit CSI/SS3) covers split sequences with no parser.
- 2026-10-29 — When a spec moves to `implemented/`, grep the whole repo for its filename. Its path and status words ("draft", "not in the app") also live in the Storybook docs (`packages/ui/.storybook/docs/system/StartHere.mdx`, `epics/*.mdx`, `WhatIsMissing.mdx`). Run Prettier on edited MDX tables, which `format:check` covers.
- 2026-10-29 — Node 24 scans `--env-file` anywhere in argv, even after the script name (`node app.js --env-file x`, also through `tsx`). A missing, unreadable or directory path makes Node exit 9 with `node: <path>: not found` before the script runs, while an existing file reaches the script as a plain argument. `process.loadEnvFile` keeps variables that are already set (an exported empty value too). So `auth:set-password` gets Node's own error for a bad env-file path; test that path end to end, not only with injected loaders.
- 2026-10-29 — A mutation-check worktree needs `packages/*/node_modules` linked as well as the root `node_modules` (e.g. `better-auth` lives in `packages/core/node_modules`); otherwise the baseline fails with `ERR_MODULE_NOT_FOUND`.
- 2026-10-29 — Better Auth 1.7.7 `internalAdapter.updatePassword(userId, hash)` returns nothing and updates only the `credential` account row with accountId = userId; for a user without one it silently changes nothing. Check `findCredentialAccount` in the same transaction first, or a reset revokes sessions, sets no password and still reports success. Prove rollback with a failure injected after both writes (run the real `deleteUserSessions`, then throw).
- 2026-10-29 — Next 16 (Turbopack) bundles a server module once for Route Handlers (`.next/server/chunks/`) and once for pages/RSC (`.next/server/chunks/ssr/`), each with its own module cache, so module-level state (`let instance`, once-only flags) exists twice per process; the `ALLOW_SIGN_UP` warning was logged twice. Keep once-per-process state on `globalThis` under a `Symbol.for(...)` key, as `getDb`'s pool does. Check with `grep -rl '<unique string>' packages/app/.next/server` (skip `.map`).
- 2026-10-29 — With `cacheComponents`, Next 16 hides a page you leave (React `<Activity>`) and shows the same instance, with its state, on the next visit. Busy-until-navigation UI (header sign-out, finished `useForm`) came back spinning after sign-up → sign-out → sign-in in one tab. Reset transient state in a `useLayoutEffect` cleanup, and test flows as same-tab round trips, not only after a fresh `browser.open` → [details](lessons/2026-10-29-activity-keeps-state-across-auth.md)

Better Auth rejects any other origin with 403 `INVALID_ORIGIN`, which the form shows as "Something went wrong".
