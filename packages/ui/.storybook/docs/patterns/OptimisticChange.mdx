# Optimistic change

How a change feels instant without lying: the list shows it at once, marks it as not yet saved, and puts everything back with a message if the server refuses. The app does this with TanStack Query optimistic updates (AGENTS.md); the components only show the states.

## Rules

| Rule                                                                                                                      | Source                        |
| ------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| An add shows a temporary row at the end at once; an edit patches the row; a delete removes it.                            | spec E01, Optimistic UI       |
| A row the server has not confirmed is pending: muted title, "Saving…", and its actions disabled.                          | spec E01, decision F3         |
| No request is ever sent with a temporary id.                                                                              | spec E01                      |
| On a refusal the list goes back to what it was and the message appears where the change was made: on the form or the row. | spec E01 ("toast-free")       |
| Forms wait for the confirmation before clearing or closing, so a refused change keeps what was typed.                     | decision F2                   |
| A confirmed new row is briefly highlighted; nothing else flashes or moves.                                                | spec E01, decision F1, Luki 8 |
| Each change is one transaction on the server: nothing is half-saved.                                                      | spec E01, Edge cases          |
