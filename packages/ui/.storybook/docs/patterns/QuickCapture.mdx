# Quick capture

How a thought becomes a task before it is forgotten: type the title, press Enter, type the next one. The owners asked for a "simple and quick tool", not "a million details" (A03). Built from `QuickAdd` and the list.

## Rules

| Rule                                                                                                               | Source                 |
| ------------------------------------------------------------------------------------------------------------------ | ---------------------- |
| Only the title is required; description and estimate wait under "Details".                                         | spec E01, R10, A03     |
| Enter in the title adds; there is always a visible "Add" button too (no keyboard-only paths).                      | spec E01, A05          |
| The new task appears at the end at once (pending), then is confirmed and briefly highlighted.                      | spec E01, decision F1  |
| After the add the field is empty and keeps focus for the next task.                                                | spec E01, After an add |
| The field clears only after the server confirmed; a refused add keeps the text and says why.                       | decision F2, spec E01  |
| The new row scrolls into view; no scroll animation or highlight under reduced motion.                              | spec E01               |
| Subtasks are captured the same way under their task; after each add the form closes and "Add subtask" takes focus. | spec E01, decision F7  |

## A list whose items have only a name

`QuickAdd` always offers "Details" with a description and an estimate. For a list whose items have only a name (the quick shopping list, E04), build the same form from primitives until a name-only quick add is built with the E04 spec (decision N3). The rules above still apply: Enter adds, a visible "Add", the field clears and keeps focus only after the server confirmed, a refusal keeps the text and says why above the field.

```tsx
const form = useForm<"name">({
  initialValues: { name: "" },
  validate: ({ name }) => ({ name: name.trim() === "" ? "Enter a name." : undefined }),
  onSubmit: addItem,
  unexpectedError: "Something went wrong. Try again.",
  resetOnSuccess: true,
});

<form {...form.formProps} className="flex flex-col gap-group">
  {form.formError ? <Alert title={form.formError} /> : null}
  <FormField label="New item" error={form.errors.name}>
    {(control) => (
      <div className="flex gap-group">
        <Input {...control} {...form.field("name")} />
        <Button type="submit" variant="primary" loading={form.pending}>
          {form.pending ? "Adding…" : "Add"}
        </Button>
      </div>
    )}
  </FormField>
</form>;
```

The field stays above the list on every width in version 1; where it sits for one-handed use on a phone is decided with the E04 spec (decision N7).
