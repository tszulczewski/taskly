# Unestimated tasks

`import { UnestimatedTasks } from "@taskly/ui";`

## 1. What it is for

Says what future expenses leaves out because it has no estimate, open tasks and open subtasks (R10, R13, D27), and lets the owner add the amounts right there, so the total can be trusted (Luki 9, R02.10).

## 2. When to use

- Under the future expenses total; `FutureExpenses` renders it when something open has no estimate, and hides it otherwise (D27).

## 3. When not to use

| Situation                                  | Use instead                                                                              | Source      |
| ------------------------------------------ | ---------------------------------------------------------------------------------------- | ----------- |
| Changing an estimate that exists           | Edit in the task's "…" (`TaskForm`)                                                      | spec E01    |
| A subtask without an estimate, in the list | the "N subtasks without an estimate" meta of its task row; here it is an item of its own | R13, D27    |
| A separate summary page                    | this collapsed line                                                                      | P04, Luki 9 |

## 4. Anatomy

| Part          | Required | Notes                                                                                                                                                                            |
| ------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trigger       | yes      | `TextAction` with the chevron: "2 tasks and 1 subtask without an estimate", collapsed by default; not shown when nothing is missing (Luki 9, D27)                                |
| Rule          | yes      | One muted sentence: they are not counted until they have an estimate (Luki 5)                                                                                                    |
| Item line     | yes      | The title (wraps), for a subtask followed by its task in muted text ("Tiles · Bathroom tiles"), and "Add estimate" at the end; lines divided by 1px `color-border-divider` (D27) |
| Estimate form | optional | In place of the line: "Amount" and "up to (optional)" with "zł", Save (primary) and Cancel (decision I4, R18)                                                                    |

## 5. Variants

None. The list names what really has to be priced (D27): an open task without subtasks, and each open subtask without an estimate, with its task. A task with subtasks is never listed itself, since its amounts come from them (R12); a partly priced task lists its unpriced subtasks, so the total never looks complete when it is not (R13). Completed subtasks and the subtasks of completed tasks are not listed. This replaces the earlier "Add estimates to its N subtasks" note (decision W3).

## 7. Behaviour and accessibility

- The trigger is a disclosure button (`aria-expanded`); the list is named by the same count.
- "Add estimate" is named with the item: "Add estimate for “Seal the bath”", and for a subtask with its task too: "Add estimate for “Tiles” in “Bathroom tiles”".
- The form is a group named `Estimate for “{title}”`, for a subtask `Estimate for “{title}” in “{task}”` (D27); Enter saves, Escape or Cancel closes it and returns focus to that item's "Add estimate". Escape does nothing while saving.
- After a save focus moves to the next item's "Add estimate" (the one before when the last was saved); after the only one, to the total (`FutureExpenses`).
- One amount saves an exact price; both, a range (R18).

## 8. Content

- The count names what is listed: "1 task without an estimate", "3 subtasks without an estimate", "2 tasks and 1 subtask without an estimate" (D27); then "Add estimate" and "They are not counted in future expenses until they have an estimate." (decision J9; not "count as zero", R10).
- Polish: "2 zadania i 1 podzadanie bez szacunku", "Dodaj szacunek", "Kwota", "do" (decision J9, D27).
