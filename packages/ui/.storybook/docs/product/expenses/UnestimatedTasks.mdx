# Unestimated tasks

`import { UnestimatedTasks } from "@taskly/ui";`

## 1. What it is for

Says which open tasks future expenses leaves out because they have no estimate (R10), and lets the owner add the amounts right there, so the total can be trusted (Luki 9, R02.10).

<Unstyled>
  <Story of={Stories.Opened} />
</Unstyled>

## 2. When to use

- Under the future expenses total; `FutureExpenses` renders it when at least one open main task has no estimate.

## 3. When not to use

| Situation                        | Use instead                                               | Source      |
| -------------------------------- | --------------------------------------------------------- | ----------- |
| Changing an estimate that exists | Edit in the task's "…" (`TaskForm`)                       | spec E01    |
| A subtask without an estimate    | the "N subtasks without an estimate" meta of its task row | R13         |
| A separate summary page          | this collapsed line                                       | P04, Luki 9 |

## 4. Anatomy

| Part          | Required | Notes                                                                                                                               |
| ------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Trigger       | yes      | `TextAction` with the chevron: "3 tasks without an estimate", collapsed by default (Luki 9)                                         |
| Rule          | yes      | One muted sentence: they are not counted until they have an estimate (Luki 5)                                                       |
| Task line     | yes      | The title (wraps) and "Add estimate" at the end; lines divided by 1px `color-border-divider`                                        |
| Estimate form | optional | In place of the line: "Amount" and "up to (optional)" with "zł", Save (primary) and Cancel (decision I4, R18)                       |
| Subtask note  | optional | Instead of "Add estimate", for a task whose subtasks all lack one: muted "Add estimates to its 2 subtasks", no action (decision W3) |

## 5. Variants

None. A task priced through its subtasks gets the subtask note in place of the button (`subtasksWithoutEstimate`): its own amount would be hidden by the sum, so the fix is on the subtasks (R12, R13).

## 7. Behaviour and accessibility

- The trigger is a disclosure button (`aria-expanded`); the list is named by the same count.
- "Add estimate" is named with the task: "Add estimate for “Seal the bath”".
- The form is a group named `Estimate for “{title}”`; Enter saves, Escape or Cancel closes it and returns focus to that task's "Add estimate". Escape does nothing while saving.
- After a save focus moves to the next task's "Add estimate", skipping tasks priced through their subtasks; after the last one, to the total (`FutureExpenses`).
- One amount saves an exact price; both, a range (R18).

## 8. Content

- "N tasks without an estimate", "Add estimate", "They are not counted in future expenses until they have an estimate." (decision J9; not "count as zero", R10).
- "Add an estimate to its subtask" / "Add estimates to its 2 subtasks" (decision W3).
- Polish: "2 zadania bez szacunku", "Dodaj szacunek", "Kwota", "do", "Dodaj szacunki do jego 2 podzadań" (decision J9).
