# App shell

`import { AppHeader, AppShell } from "@taskly/ui";`

## 1. What it is for

Frames every signed-in page with a quiet top bar and one centred column, so the list is the only thing that asks for attention.

<Story of={Stories.Playground} />

## 2. When to use

- Every signed-in page (`/` and later screens), around the page content.

## 3. When not to use

| Situation                             | Use instead | Source           |
| ------------------------------------- | ----------- | ---------------- |
| Sign-in and sign-up                   | `AuthCard`  | sign-in spec     |
| A side bar or panels next to the list | not used    | Q2, R01.5, A01.3 |

## 4. Anatomy

| Part           | Required | Notes                                                                                         |
| -------------- | -------- | --------------------------------------------------------------------------------------------- |
| Top bar        | yes      | `<header>` with a 1px `color-border-divider` line under it (tokens: "line under the top bar") |
| App name       | yes      | "Taskly", strong body text                                                                    |
| Theme toggle   | yes      | `ThemeToggle`                                                                                 |
| Sign out       | yes      | Ghost `Button` opening a `Menu`: "Sign out of this device", "Sign out of other devices" (#78) |
| Sign-out error | optional | `Alert` under the bar: "Could not sign out. Try again." (decision E7)                         |
| Column         | yes      | `<main>`, at most `layout-content-max-width` 980px, page gutter, `space-page-top` (P01)       |

No bottom navigation on phones in version 1: it would have one item, because version 1 has one screen (P07; owner decision E1).

## 5. Variants

None. `AppHeader` is exported on its own for pages that need only the bar.

## 7. Behaviour and accessibility

- Landmarks: `banner` (the bar) and `main`. The page heading is the `h1` inside `main`, not the app name: one per page, `text-heading font-strong`, naming what the page shows (the list's name), as in Product / Tasks / Screens.
- Tab order: theme toggle → Sign out → page content. "Sign out" is a menu button (`aria-haspopup="menu"`): Enter, Space or a click opens it with focus on the first item; Escape closes it and returns focus. While a sign-out runs it shows the spinner and opens nothing.
- Why a menu, not a second button: two text buttons and the theme icons do not fit one row at 320px (E10). Signing out everywhere is rare; this device stays one menu choice away.
- The sign-out failures are announced (`role="alert"`). Signing out other devices says nothing when it works, as every success (design system, "If … then use …"): the menu closes and the button is ready again. Covered by the Sign Out Failed, Sign Out Other Devices and Sign Out Other Devices Failed tests.

## 10. API

<ArgTypes of={Stories} />

`onSignOut` resolves `true` when the server confirmed; the app then clears the Query cache and goes to `/sign-in` (spec). `onSignOutOtherDevices` resolves `"done"` when the server ended every other session of the user (the page stays and nothing is shown), `"failed"` for the Alert, or `"sessionEnded"` when this session was already gone: the app clears the cache and goes to `/sign-in`, so the button stays busy as after `onSignOut` (#78, threat T-06; sign-in spec, Edge cases).

</AppShell>
