# Estimate range

`import { EstimateRange } from "@taskly/ui";`

## 1. What it is for

Shows what a task is expected to cost, as a range or one exact amount in złoty, in the same place on every row, so the owner can compare tasks without opening them. On a task with subtasks it is their sum (R12).

  <Story of={Stories.Playground} />

## 2. When to use

- The right end of a task or subtask row (R02.5, spec E01).
- Not the future expenses total: `FutureExpenses` shows its range larger, in one line of its own (P04).

## 3. When not to use

| Situation                      | Use instead                  | Source     |
| ------------------------------ | ---------------------------- | ---------- |
| Typing an amount               | `Input` with the suffix "zł" | spec E01   |
| A spent (real) cost            | not in version 1             | D17, R02.8 |
| A total shown as several tiles | one line of future expenses  | P04, R02.7 |

## 4. Anatomy

| Part        | Required | Notes                                                                                 |
| ----------- | -------- | ------------------------------------------------------------------------------------- |
| Range       | one of   | "1 200–1 500 zł": en dash, no spaces around it, one "zł" (tokens rule 5); never wraps |
| Exact price | one of   | "450 zł": one amount when min equals max (R18, D24)                                   |
| No estimate | one of   | "No estimate" in `color-text-muted` (spec E01, R02.5)                                 |

The value arrives formatted: the app formats grosze at the UI edge with `formatPlnRange`, which gives one amount when min equals max (standards §6, P1). The component never calculates, and a summed estimate looks the same as a typed one (decision W2).

## 5. Variants

None. The empty text can be translated with `emptyText`.

## 6. States

<Unstyled>
  <Story of={Stories.States} />
</Unstyled>

Three states: a range, an exact price, or none. Loading, error and interactive states belong to the row. Covered by the Exact Price and No Estimate tests.

## 7. Behaviour and accessibility

- Plain text, read in row order after the title. No icon or colour carries meaning; "No estimate" is words (WCAG 1.4.1).
- Tabular figures and the strong weight (Luki 1, tokens rule 5); amounts stay on one line (`white-space: nowrap`).

## 8. Content

- PLN only; grosze shown only when not zero ("62 500,50 zł").
- Thousands grouped with a non-breaking space.

## 11. Code

```tsx
<EstimateRange value={task.estimate} />
```

In Taskly: the app passes `formatPlnRange(min, max)` or `null`.

```tsx
<EstimateRange
  value={task.estimate ? formatPlnRange(task.estimate.minGrosze, task.estimate.maxGrosze) : null}
/>
```
