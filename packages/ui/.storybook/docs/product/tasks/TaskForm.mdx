# Task form

`import { TaskForm } from "@taskly/ui";`

## 1. What it is for

Changes a task or subtask where it stands: the row turns into this form, prefilled, and turns back after Save or Cancel. The list and its order stay in view.

  <Story of={Stories.Playground} />

## 2. When to use

- "Edit" in a row's "…" menu, for tasks and subtasks (spec E01, Edit). `TaskRow` renders it; the app does not place it by hand.

## 3. When not to use

| Situation                | Use instead         | Source    |
| ------------------------ | ------------------- | --------- |
| Adding a task or subtask | `QuickAdd`          | spec E01  |
| Details in a drawer      | the form in the row | R02.6, Q2 |
| Deleting                 | `DeleteTaskDialog`  | spec E01  |

## 4. Anatomy

| Part           | Required | Notes                                                                                                       |
| -------------- | -------- | ----------------------------------------------------------------------------------------------------------- |
| Error          | optional | `Alert` above the fields when saving failed; what was typed stays                                           |
| Title          | yes      | Focused when the form opens                                                                                 |
| Estimate       | optional | As in Quick add: "Amount" and "up to (optional)", suffix "zł", `inputmode="decimal"` (R18)                  |
| Sum (subtasks) | instead  | A task with subtasks: "Sum of subtasks: 300–400 zł" and "Change the amounts on the subtasks." as text (R12) |
| Description    | optional | Behind the "Description" toggle, open when the task has one                                                 |
| Save           | yes      | Primary; "Saving…" with a spinner while sending                                                             |
| Cancel         | yes      | Secondary; Escape does the same                                                                             |

The form sits on `color-surface-raised` in place of the row (tokens: raised for an open row).

## 5. Variants

| Variant                | Choose it when                                                                                             | Source        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- | ------------- |
| Amounts (default)      | A subtask, or a task without subtasks.                                                                     | spec E01      |
| `summedEstimate` given | A task with subtasks: its estimate is their sum, so it is shown as text, not as fields; `null` means none. | R12, D22, R15 |

Text, not disabled fields: a disabled field looks editable and screen readers skip it. The task's own figure is kept unchanged and comes back when its last subtask goes (R15).

## 7. Behaviour and accessibility

- The form is named `Edit “{title}”` (`aria-label`), so a screen reader hears what is being edited.
- Focus moves to Title when the form opens; after Save or Cancel it returns to the row's "…" button (decision F6). Covered by the TaskList unit tests.
- The form waits for the server before closing; while it waits Cancel and Escape do nothing, so the result is never unknown (decision F2).
- Errors are linked with `aria-describedby`; the first invalid field takes focus.

## 8. Content

- Buttons: "Save", "Cancel". Labels as in Quick add; the sum reads "Sum of subtasks:", "no estimate yet", "Change the amounts on the subtasks."
- Messages as in Quick add (spec E01; title message an example, decision E3).

## 11. Code

```tsx
<TaskForm
  initialValues={{ title: "Seal the bath", amount: "", upTo: "", description: "" }}
  validate={validateTaskForm}
  onSubmit={(values) => updateTask.mutateAsync({ id, ...values })}
  onCancel={() => setEditing(false)}
  summedEstimate={task.subtasks.length > 0 ? task.estimate : undefined}
/>
```
