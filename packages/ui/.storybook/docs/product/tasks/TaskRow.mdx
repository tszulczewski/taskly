# Task row

`import { TaskRow } from "@taskly/ui";`

## 1. What it is for

Shows one task or subtask as a single calm line: what to do and what it may cost. Everything else (description, subtasks, adding a subtask) opens in place, so the owner can scan many small tasks and choose the next one.

## 2. When to use

- Every task and subtask on the task list; `TaskList` renders the rows (spec E01, R02.1).

## 3. When not to use

| Situation                          | Use instead                | Source       |
| ---------------------------------- | -------------------------- | ------------ |
| A card per task                    | rows on one `Surface`      | R02.1, A01.3 |
| Task details in a drawer or window | the row's expanded content | R02.6, Q2    |
| A table with many amount columns   | one amount per row         | A04, R02.5   |

## 7. Behaviour and accessibility

- **Order:** handle (from 640px) → checkbox → title (when it opens details) → "…" → (expanded) subtasks → "Add subtask". The arrow is not a tab stop.
- **Completing:** the checkbox completes or reopens the row at once; a task with open subtasks asks first (`CompleteTaskDialog`). The list moves the row and keeps focus on its checkbox (see Patterns / Complete and reopen).
- **Moving:** by the handle (mouse, keyboard), a long press on the row (touch), or Move up / Move down in "…"; a subtask moves only among its task's subtasks (decisions G1, G2). See Drag handle and Patterns / Reorder.
- **Markers:** checkbox items in "…", announced as checked or not; the change shows at once (Optimistic change).
- **Places:** "Places…" opens the picker beside "…" with focus inside; Escape returns focus to "…".
- **Title:** a disclosure button ("Paint the bathroom ceiling, collapsed"); Enter or Space toggles. A click or tap anywhere on the title, estimate or meta line does the same; from 640px so does the arrow (decision J1). One control per row, so a screen reader hears the task once. The content opens over `motion-duration-base` (Luki 8).
- **Menu:** `Menu` with `modal={false}`; arrow keys move, Escape closes and returns focus to "…". Edit and Add subtask move focus into their form; Delete hands over to the list's dialog.
- **After Edit / Cancel:** focus returns to "…" (decision F6). After "Add subtask" Cancel: back to "Add subtask".
- **Pending:** actions are disabled so no request is sent with a temporary id (spec E01). "Saving…" says why (decision F3).
- **Highlight:** `scrollIntoView` with smooth scrolling; no scroll animation and no highlight under `prefers-reduced-motion: reduce` (spec E01).
- **Targets:** checkbox, arrow and "…" are 44 × 44 px; the title's target is the whole text block, at least 44px high (K1).

## 8. Content

- Menu: "Add subtask", "Edit", "Delete" (spec E01); "Places…", "Important", "Urgent", "Move up", "Move down" (decision G3). Meta: "1 subtask" / "3 subtasks".
- No estimate: "No estimate" (spec E01).

## 11. Code

`TaskList` renders rows; a row on its own is only for tests and stories.

```tsx
<ul aria-label="Tasks">
  {tasks.map((task) => (
    <TaskRow
      key={task.id}
      task={task}
      validate={validateTaskForm}
      onEdit={edit}
      onAddSubtask={addSubtask}
      onRequestDelete={askToDelete}
    />
  ))}
</ul>
```
