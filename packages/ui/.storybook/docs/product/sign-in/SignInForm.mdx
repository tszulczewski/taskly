# Sign-in form

`import { SignInForm } from "@taskly/ui";`

## 1. What it is for

Lets the owner get back into their renovation plan with an email and a password, and says plainly what went wrong when it fails.

| ----------------- | -------- | -------------------------------------------------------------------------------------- |

## 7. Behaviour and accessibility

- **Order:** Email → Password → show-password button → Sign in → Create an account. Enter in a field submits.
- **Validation:** a field is checked when the user leaves it after typing, and every field on submit; focus moves to the first invalid field (pattern Form, spec Accessibility). Covered by the Missing Fields test.
- **Errors:** field messages are linked with `aria-describedby`; the form error is announced (`role="alert"`, WCAG 4.1.3).
- **Double submit:** blocked while sending, so a second attempt is not spent against the rate limit (spec, UI/UX). Covered by the Pending test.
- **Password:** hidden again on submit (Q10).
- **Targets:** fields, buttons and the eye button are 44px on phones, 36px from 640px (K1, V1).

## 8. Content

- Labels: "Email", "Password"; button "Sign in"; link "Create an account" (spec).
- Error messages never say whether the email exists (spec, Messages).
- Field messages come from the shared schema `signInInput`; the ones in these stories are examples (decision E3).

## 10. API

<ArgTypes of={Stories} />

`validate` and `onSubmit` come from the app (P1): `validate` applies `signInInput`; `onSubmit` calls `authCall` and maps the response to `{ ok: true }` or `{ ok: false, formError }`.

## 11. Code

```tsx
<AuthCard title="Sign in">
  <SignInForm
    validate={(values) => fieldErrorsOf(signInInput, values)}
    onSubmit={signIn}
    signUpHref={signUpOpen ? "/sign-up" : undefined}
  />
</AuthCard>
```
