# Place picker

`import { PlacePicker } from "@taskly/ui";`

## 1. What it is for

Puts a task or subtask in one or more places, such as "Bathroom" and "Hall", and lets the owner create, rename, recolour or delete places without leaving the list (D09, D21).

## 2. When to use

- In the popover that "Places…" in a row's "…" menu opens (decision G3). `TaskRow` renders it when it gets `places`.

## 3. When not to use

| Situation                         | Use instead                      | Source      |
| --------------------------------- | -------------------------------- | ----------- |
| Showing a task's places           | `PlaceTag` in the meta line      | Luki 6      |
| Marking a task important / urgent | "Important" / "Urgent" in "…"    | D07, G3     |
| Filtering the list by place       | not in version 1                 | P03, P4     |
| A page to manage places           | "Edit places" inside this picker | decision G6 |

## 4. Anatomy

| Part            | Required | Notes                                                                                                                  |
| --------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| Title           | yes      | "Places for “Hang the curtain rods”"; also names the popover                                                           |
| Places          | one of   | A `Checkbox` per place with its `PlaceTag` as the label; or "No places yet." in muted text                             |
| New place       | one of   | A field and "Create" (secondary) on one line; a `PlaceColorPicker` under it from the seventh place (decision G4)       |
| Limit message   | one of   | "You can have up to 10 places. Delete one to add another." instead of New place (decision G5)                          |
| Edit places     | optional | Muted `TextAction`; opens the edit view (decision G6)                                                                  |
| Edit view       | —        | "Back to choosing", then each place with "Edit"; the place being edited shows Name, Colour, Save, Cancel, Delete place |
| Delete question | —        | "Delete “Hall”? It is removed from every task." with Delete place (danger) and Cancel, in place                        |

Parts are `space-between-groups` apart; the panel is the popover's raised surface with its 1px edge (K2).

## 7. Behaviour and accessibility

- **Order:** places (checkboxes) → New place → Create → (Colour) → Edit places. In the edit view: Back to choosing → each place's Edit.
- **Focus:** opening the popover from the menu moves focus into it; switching views puts focus on the first control of the new view ("Back to choosing" or "Edit places"); after a create focus stays in New place. Escape closes the popover and focus returns to "…".
- **Ticks** save at once and roll back with a message in the row if the server refuses (Optimistic change pattern).
- **Delete** asks once, in place, because it removes the place from every task (Delete confirmation pattern, decision G6).
- Checkboxes and swatches are 44 × 44 px targets (K1).

## 8. Content

- "New place", "Create", "Edit places", "Back to choosing", "Delete place" (decisions G3–G6; wording is a proposal).
- Name rules: not empty, at most 30 characters, unique in the list (decision G4). Messages are examples from the app.

## 10. API

`PlacePicker` props (the demo above wraps it with a simulated server):

| Prop           | Type                                                 | Notes                                    |
| -------------- | ---------------------------------------------------- | ---------------------------------------- |
| `taskTitle`    | `string`                                             | Names the panel.                         |
| `places`       | `Place[]`                                            | Every place of the list.                 |
| `selectedIds`  | `string[]`                                           | The task's places.                       |
| `onToggle`     | `(placeId, assigned) => void`                        | Saves at once (optimistic).              |
| `onCreate`     | `(values) => Promise<SubmitResult<"name">>`          | Creates a place and puts the task in it. |
| `onUpdate`     | `(placeId, values) => Promise<SubmitResult<"name">>` | Rename and recolour.                     |
| `onDelete`     | `(placeId) => Promise<boolean>`                      | `false` or a throw shows the failure.    |
| `validateName` | `(name, placeId?) => string \| undefined`            | The app's rules (G4).                    |
| `atLimit`      | `boolean`                                            | The app's limit is reached (G5).         |
| `text`         | `Partial<PlaceText>`                                 | Translations.                            |

## 11. Code

`TaskRow` opens it; the app passes `places` to `TaskList`.

```tsx
<TaskList
  {...listProps}
  places={{
    all: places,
    atLimit: places.length >= 10,
    validateName: placeNameRule(places),
    onToggle: (taskId, placeId, on) => toggle.mutate({ taskId, placeId, on }),
    onCreate: (taskId, values) => createPlace(taskId, values),
    onUpdate: (placeId, values) => updatePlace(placeId, values),
    onDelete: (placeId) => deletePlace(placeId),
  }}
/>
```
