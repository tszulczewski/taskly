# Checkbox

`import { Checkbox, Label } from "@taskly/ui";`

## 1. What it is for

Lets the user mark one thing as done or chosen with a single press, and see at a glance which things are.

<Unstyled>
  <Story of={Stories.WithLabel} />
</Unstyled>

## 2. When to use

- Completing and reopening a task or subtask from its row (backlog E03-S01, R02.1, R02.2).
- Marking an item of a list that is not tasks as done, such as a bought item on the quick shopping list (E04), with a visible `Label` holding the item's name (decisions N5, N6; Patterns › List).
- Choosing several places for a task in `PlacePicker` (E02-S03). The "Important" / "Urgent" markers in the row menu are menu checkbox items (`MenuCheckboxItem`, decision G3).

## 3. When not to use

| Situation                                                        | Use instead                      | Source       |
| ---------------------------------------------------------------- | -------------------------------- | ------------ |
| One choice out of several (one colour for a place)               | `RadioGroup`                     | WAI-ARIA APG |
| A setting that applies at once and is not part of a list (theme) | `RadioGroup variant="segmented"` | P4, Luki 2   |
| An action ("Delete task")                                        | `Button`                         | —            |

## 4. Anatomy

| Part       | Required     | Notes                                                                                             |
| ---------- | ------------ | ------------------------------------------------------------------------------------------------- |
| Target     | yes          | 44 × 44 px (36 × 36 px from 640px), transparent, holds the box (T10, K1)                          |
| Box        | yes          | `checkbox-size` 20px, `checkbox-radius` 6px, 1px `color-border-control` (R02.1, T1, T8, T10)      |
| Check mark | when checked | Lucide `Check` in `color-text-on-action` on `color-action-primary` (tokens: on-action "znacznik") |
| Label      | yes          | `Label htmlFor`, or `aria-label` when the row's title already sits next to it                     |

## 5. Variants

None. There is no indeterminate ("some subtasks done") state: progress is written as "1/3" in the row (Luki 6), so the box is only checked or not.

## 7. Behaviour and accessibility

- **Keyboard:** Tab reaches it; Space toggles; Enter does nothing (WAI-ARIA APG, checkbox). Covered by the Playground test.
- **Role and state:** `role="checkbox"` with `aria-checked="true|false"` (Radix). A screen reader says "Paint the bathroom ceiling, checkbox, checked".
- **Name:** a `Label` with `htmlFor`; clicking the label toggles too. Covered by the WithLabel test. In a task row the title is already visible next to the box, so `TaskCheckbox` names it with `aria-label`: the action and the task, “Complete “Paint the bathroom ceiling”” (decision J9).
- **Target size:** 44 × 44 px (36 × 36 px from 640px) around a 20px box (T10, spec E01).
- **Colour:** the check mark, not only the green fill, shows the state (WCAG 1.4.1); the box border has 6.94:1 / 6.31:1 on the list surface (WCAG 1.4.11).
- **Motion:** the fill changes over `motion-duration-quick` (Luki 8), at once with reduced motion.

## 8. Content

- A visible `Label` is the thing itself, not an instruction: "Paint the bathroom ceiling", not "Mark as done" (glossary, Luki 5).
- A box named only by `aria-label`, beside a title that is already visible, is named like an icon button: the action and the object, “Complete “Paint the bathroom ceiling”” (`TaskCheckbox`, decision J9). The two rules do not conflict: one is a visible label, the other an accessible name.
- Long labels wrap next to the box. In a list row the text block is centred against the target while it fits in it (one line, or a title with a second line); longer text grows downwards and the box stays at the top of the row, level with the top of the text rather than with its first line. A row does not grow to line the box up with the first line (decision U1).
- Polish labels: "Zeskrobać starą farbę".

## 10. API

<ArgTypes of={Stories} />

`checked`, `defaultChecked` and `onCheckedChange` use plain booleans. Other props go to the Radix root (`id`, `name`, `value`, `disabled`, `required`).

## 11. Code

Minimal:

```tsx
<div className="flex items-center">
  <Checkbox id="primer" />
  <Label htmlFor="primer">Buy primer</Label>
</div>
```

In Taskly: completing a task from its row.

```tsx
<Checkbox
  aria-label={`Complete “${task.title}”`}
  checked={task.completed}
  disabled={task.pending}
  onCheckedChange={(done) => setCompleted(task.id, done)}
/>
```

In a list that is not tasks: an item marked done, named by its visible label (decisions N5, N6). `Label` has no done look of its own, so the muted, struck-through text is a `span` inside it; the name keeps the regular weight.

```tsx
<Checkbox id={id} checked={item.done} onCheckedChange={toggle} />
<Label htmlFor={id}>
  <span className={cn("break-words", item.done && "text-muted line-through")}>{item.name}</span>
</Label>
```
