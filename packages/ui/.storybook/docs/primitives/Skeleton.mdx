# Skeleton

`import { Skeleton } from "@taskly/ui";`

## 1. What it is for

Shows the shape of content that is still loading, so the page does not jump and the user knows something is coming.

<Unstyled>
  <Story of={Stories.ListLoading} />
</Unstyled>

## 2. When to use

- The task list while it loads for the first time (spec E01: "Loading: a skeleton").
- The future expenses line while totals load (backlog E03-S02).

## 3. When not to use

| Situation                                     | Use instead                          | Source       |
| --------------------------------------------- | ------------------------------------ | ------------ |
| Waiting for a button's action                 | `Button loading`                     | sign-in spec |
| A change that is already shown optimistically | the pending row (dimmed)             | spec E01     |
| Waits after the first load                    | keep showing the data already loaded | proposal C3  |

## 4. Anatomy

| Part   | Required             | Notes                                                                                                      |
| ------ | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| Bar    | yes                  | `color-surface-raised`, `radius-control`; one text line high by default (`h-lh`) (Luki 8)                  |
| Status | yes, once per region | A visually hidden `role="status"` text ("Loading tasks…") in the region, which also has `aria-busy="true"` |

## 5. Variants

None. Size comes from token utilities: text line (default), `h-control` for a field, widths as fractions of the row (`w-2/3`, `w-1/2`) — see Variants story.

## 6. States

<Unstyled>
  <Story of={Stories.States} />
</Unstyled>

One state: shown. It never pulses or shimmers (Luki 8, tokens rule 12, R02.12). Hover, focus, pressed, disabled, selected and error do not apply; a load that fails replaces the skeleton with an `Alert` and "Try again".

## 7. Behaviour and accessibility

- Bars are `aria-hidden`: a screen reader hears one "Loading tasks…" from the status text, not a list of empty shapes (WCAG 4.1.3). Covered by the ListLoading test.
- The loading region has `aria-busy="true"` until the content arrives.
- No motion at all, so nothing to reduce (WCAG 2.3.3).

## 8. Content

- Only the status text: "Loading tasks…" / "Wczytywanie zadań…" (Luki 5).
- Draw bars in the shape of the real rows: one bar per line of text, the first one longer.
- A skeleton row is as high as a real row, so the list does not move when the rows arrive: the bars sit in the same text block, one target high (`min-h-touch`) between the row's padding. On phones two bars fit in it at the meta size (`text-meta` on their box), as a row there has two lines (title, estimate); from 640px the block is 36px and holds one bar, as a row there has one line (V1). Covered by the Task list › Loading test (decision N8).
- A row with one line of text (a shopping item: a name only) gets one bar at body size (the default height, `h-lh`) in the same target-high block, `w-2/3`; draw three rows, as the task list does (decision U2).
- Bar widths are fractions of the text block (`w-2/3`, `w-1/3`): proportions, not design values, so `check:tokens` allows them (decision U3).
- Bars start where the row's text starts: the columns before it (the drag handle and the arrow from 640px, the checkbox) stay empty, `w-touch` each with the row's `space-group` gap. Covered by the Task list › Loading Lines Up test (decision O3).

## 10. API

<ArgTypes of={Stories} />

Every `<div>` attribute is passed through; use `className` for size only.

## 11. Code

Minimal:

```tsx
<Skeleton className="w-1/2" />
```

In Taskly: the task list loading.

```tsx
<Surface aria-busy="true">
  <span className="sr-only" role="status">
    Loading tasks…
  </span>
  {[0, 1, 2].map((i) => (
    <div key={i} className="border-t border-divider px-inset py-row-y first:border-t-0">
      <div className="flex min-h-touch flex-col justify-center gap-inline text-meta">
        <Skeleton className="w-2/3" />
        <Skeleton className="w-1/3" />
      </div>
    </div>
  ))}
</Surface>
```
