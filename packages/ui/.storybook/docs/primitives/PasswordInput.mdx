# Password input

`import { PasswordInput } from "@taskly/ui";`

## 1. What it is for

Lets the user type a password without showing it to people nearby, and check what they typed with one press.

<Unstyled>
  <Story of={Stories.Playground} />
</Unstyled>

## 2. When to use

- The password on `/sign-in` (`autoComplete="current-password"`) and on `/sign-up` (`autoComplete="new-password"`, hint "At least 10 characters") (sign-in spec, Q10).
- Anywhere else a secret is typed. Version 1 has no other place.

## 3. When not to use

| Situation                    | Use instead                                   | Source            |
| ---------------------------- | --------------------------------------------- | ----------------- |
| Any value that is not secret | `Input`                                       | —                 |
| A "Repeat password" check    | nothing: the show-password button replaces it | sign-in spec, Q10 |

## 4. Anatomy

| Part                 | Required | Notes                                                                                                        |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| Frame and value      | yes      | Same as `Input`: 44px, `color-border-control`, `radius-control` (K1, T1, T8)                                 |
| Show-password button | yes      | Inside the field on the right, 44 × 44 px, Lucide `Eye` / `EyeOff` in `color-text-muted` (sign-in spec, Q10) |

## 5. Variants

None. The sign-in and sign-up fields differ only in `autoComplete` and the hint, which come from the caller.

## 7. Behaviour and accessibility

- **Keyboard:** Tab goes from the field to the show-password button; Space or Enter toggles it. Covered by the Playground test.
- **Button name and state:** the name stays "Show password"; `aria-pressed` tells whether the password is shown, so screen readers say "Show password, toggle button, pressed" (sign-in spec Q10, WAI-ARIA APG: button, toggle).
- `aria-controls` points the button at the field.
- **Reset on submit:** the field returns to hidden when its form is submitted, so a shown password is not left on screen after signing in. Covered by the HiddenAgainAfterSubmit test (sign-in spec, Q10).
- **Target size:** the button covers the full 44px height of the field and 44px width (sign-in spec, Q10).
- **Password managers:** pass `autoComplete` and `name`; the component does not change them (WCAG 1.3.5).

## 8. Content

- Label: "Password" / "Hasło". The rule goes in the hint before typing: "At least 10 characters" / "Co najmniej 10 znaków" (sign-in spec; standards: minimum length 10).
- The button name is passed as `toggleLabel` in Polish: "Pokaż hasło".
- Errors say what to do: "Enter your password.", "Use at least 10 characters." (Luki 5).

## 10. API

<ArgTypes of={Stories} />

Every native `<input>` attribute except `type` (the component owns it) goes to the field. `id` is generated when omitted, so `aria-controls` always has a target.

## 11. Code

Minimal:

```tsx
<FormField label="Password">
  {(field) => <PasswordInput {...field} autoComplete="current-password" />}
</FormField>
```

In Taskly: the sign-up password.

```tsx
<FormField label="Password" hint="At least 10 characters" error={errors.password}>
  {(field) => <PasswordInput {...field} name="password" autoComplete="new-password" />}
</FormField>
```
