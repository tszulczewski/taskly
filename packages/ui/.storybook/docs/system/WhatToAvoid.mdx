# What to avoid

Three lists: the anti-patterns of this product (from the owner's references), the generic look of generated interfaces, and implementation mistakes. Each item says how to spot it on screen and in code, why it is a problem, and what to do instead. Component pages show the same as "Do and don't".

## 1. Taskly's anti-patterns

| Avoid                               | Spot it on screen / in code                                                                                                                   | Why                                                   | Instead                                                     | Source               |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- | -------------------- |
| A loud bar on a white page          | A full-width bar in a saturated colour over pure white. Code: a saturated `background` on a bar or section, `#fff` as the page.               | "Too bright"; colour stops meaning anything.          | Dark default theme, colour only on actions and "completed". | A01.1, Q1            |
| A board of columns                  | Status columns side by side, scrolling sideways, a card per task. Code: `Board`, `Column`, `Card`, a grid by status.                          | "In our case it needs to be a list."                  | One list of rows (`TaskList`).                              | A01.2, R02.1         |
| An overloaded task                  | Round coloured checkboxes, timers, rows of small icons, a window over the board. Code: many icon buttons in a row, a modal for details.       | Too much on one task; the window hides the list.      | Title, places, markers, amount; details open in the row.    | A01.3, Q2            |
| A drawer or a panel in a panel      | Details sliding in from the side over the list; a grey box inside a box. Code: `Sheet`, `Drawer`, a `Surface` inside a `Surface`.             | "Too much separated windows and panels."              | Open in the row (`TaskRow`, `TaskForm`).                    | R02.6, tokens rule 8 |
| Tiles of numbers                    | A grid of boxes with a capital label and a big number (Estimated, Spent, Budget left). Code: `grid-cols-4` of cards with `uppercase`.         | Version 1 has one total; tiles look like a dashboard. | One line: `FutureExpenses`.                                 | R02.7, P04           |
| Spent, budget, AI estimate, sharing | "Spent", "Budget left", "Estimate with AI ✨", avatars, "Share".                                                                              | Not in version 1 (a budget even contradicts D06).     | Only the version 1 scope.                                   | R02.8, P03           |
| A long form to add a task           | Several required fields, a wizard, project settings first. Code: a create schema with many required fields, a modal as the only way to add.   | "It has to be a simple and quick tool."               | `QuickAdd`: the title alone, details later.                 | A03, R02.9           |
| A spreadsheet                       | Many columns, editing in cells, sorting headers. Code: a data-table component as the main view.                                               | "I wanted to do it in Excel, but it got chaotic."     | One row per task, one amount.                               | A04, R02.5           |
| A tool for programmers              | Task ids ("EA-490"), jargon (issue, backlog, scope), actions only by shortcut, a command palette. Code: key handlers with no visible control. | "I'm not an IT specialist."                           | Plain words; every action has a visible control.            | A05, R01.6           |
| Pastel pills for places             | Each room as a coloured, filled pill. Code: `rounded-full bg-…` around a place name.                                                          | Colour everywhere; it competes with the content.      | `PlaceTag`: an 8px dot and the name in neutral text.        | R02.3, Q3            |

## 2. The generic look of generated interfaces

| Avoid                                   | Spot it on screen / in code                                                                          | Why                                                  | Instead                                                                     | Source               |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------- | -------------------- |
| Gradients in backgrounds, text, buttons | Violet-to-blue fills, rainbow headings. Code: `bg-gradient-to-*`, `bg-clip-text`, `linear-gradient`. | Says nothing about the product; loud.                | Flat token colours.                                                         | A02, tokens rule 1   |
| Glass and blur                          | Frosted panels, blurred backgrounds. Code: `backdrop-blur`, translucent `bg-white/10`.               | Lowers contrast; decoration.                         | Solid surfaces: `bg-list`, `bg-raised`.                                     | A02, tokens rule 1   |
| Glow                                    | Coloured light around buttons or cards. Code: coloured `shadow-*`, `drop-shadow`.                    | Decoration that competes with the content.           | The focus ring only for focus.                                              | A02, tokens rule 1   |
| Emoji instead of icons                  | 🚀 ✅ 🏠 in headings or buttons. Code: emoji in strings.                                             | Inconsistent, read aloud oddly.                      | A word; a Lucide icon only for a known gesture.                             | tokens rule 11       |
| Sparkles as the sign of AI              | ✨ next to a feature. Code: `Sparkles` icon, "✨".                                                   | The generic AI signature; AI is not in version 1.    | Nothing; describe what a feature does in words.                             | A02, R02.8           |
| Three identical cards with an icon      | A row of equal cards: icon, title, two lines. Code: `grid-cols-3` of the same card.                  | Fills space without telling the user anything.       | A list, or one sentence.                                                    | A02                  |
| Everything in pills                     | Statuses, tags and buttons all fully rounded and filled. Code: `rounded-full` everywhere.            | Nothing stands out when everything is a badge.       | Words in muted text (`Markers`), dots for places.                           | A02, Luki 4          |
| A card in a card                        | A bordered box inside a bordered box. Code: a `Surface` inside a `Surface`.                          | "Too many panels."                                   | One surface; rows divided by a line.                                        | A02, R02.6           |
| A shadow as the only separation         | Every card floats. Code: `shadow-*` on every container.                                              | Depth by tone and line is calmer.                    | `color-surface-raised` and a 1px line.                                      | tokens rule 1, R01.1 |
| Everything centred                      | Centred headings, text and lists in the whole page. Code: `text-center`, `items-center` on content.  | Hard to scan; amounts no longer line up.             | Left-aligned text, amounts right-aligned; only the sign-in card is centred. | R02.1, R02.5         |
| Capital labels with wide spacing        | "ESTIMATED", "BUDGET". Code: `uppercase tracking-wide`.                                              | Another signature of the generic look; hard to read. | Sentence case, hierarchy by text colour.                                    | P12, tokens rule 4   |

## 3. Implementation mistakes

| Avoid                                    | Spot it in code                                                                                                    | Why                                                              | Instead                                                                   | Source                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------- |
| A value outside the tokens               | `#4CB59B`, `rgb(…)`, `text-gray-500`, `p-[13px]`, `rounded-xl`, `duration-300`. `npm run check:tokens` lists them. | Themes and decisions stop applying; the next screen drifts.      | A semantic utility (`text-muted`, `p-inset`, `rounded-control`).          | task rule 3, tokeny.md    |
| A variant added in passing               | A new `variant`, `size` or one-off `className` override on a primitive for one screen.                             | The system grows without a decision; screens stop matching.      | Use what exists; otherwise follow Contributing.                           | task rule 6, Contributing |
| A `div` instead of a button              | `<div onClick>`, `<span role="button">` without keys, a link with `href="#"` that acts.                            | No keyboard, no name, no focus.                                  | `Button`, `TextAction`; `Link` only to navigate.                          | WCAG 2.1.1, 4.1.2         |
| A placeholder instead of a label         | `<Input placeholder="Email" />` without `FormField`.                                                               | The name disappears while typing; low contrast.                  | `FormField label="Email"`; a placeholder only as an example.              | WCAG 3.3.2                |
| A status shown only by colour            | A red or green dot or text with no word.                                                                           | Not seen by everyone; not read aloud.                            | A word, plus strike-through for completed; a dot always beside a name.    | WCAG 1.4.1, tokens rule 3 |
| A disabled button with no explanation    | `disabled` with nothing saying why.                                                                                | The user is stuck.                                               | Keep it enabled and say what is missing on submit, or a visible sentence. | P4, Patterns / Form       |
| A toast for an error that needs action   | `toast.error("Could not save")`.                                                                                   | It disappears before the user can act; it is far from the cause. | The error where it happened: field, form, row, line.                      | spec E01, P4              |
| A tooltip with information needed to act | A rule or a limit only in a tooltip.                                                                               | Hidden on touch; easy to miss.                                   | Visible text next to it.                                                  | P4                        |
| An icon button without a name            | `<Button size="icon">` without `aria-label`.                                                                       | Read as "button".                                                | `aria-label` with the action and the object.                              | WCAG 4.1.2                |
| `fetch` or business rules in a component | A component calling the API, computing totals or checking roles.                                                   | Breaks the layering; untestable stories.                         | Props in, callbacks out; rules in `@taskly/core`.                         | P1, standards §5          |
