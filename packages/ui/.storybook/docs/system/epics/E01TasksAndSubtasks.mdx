# E01 Tasks and subtasks

Backlog E01 (#11): E01-S01 add a task with a description and an estimate range (#15), E01-S02 subtasks with their own estimate that changes nothing in the task (#16). Spec: `.ai/specs/2026-10-16-tasks-and-subtasks.md` (PR A: data and services; PR B: routes and the screen; PR C: subtasks). Screens S5 and S6.

## Flow

1. The owner opens `/` and sees one list on one surface; while it loads, static grey rows.
2. They type a title in quick add and press "Add" (or Enter). The row appears at once, muted with "Saving…", and is confirmed or rolled back with the message on the form; focus stays in quick add for the next task.
3. "Details" in quick add opens the description and the estimate (min and max in złoty) for those who want them now; only the title is required.
4. Pressing a task's title opens the row in place: the description, the subtasks and "Add subtask". The estimate stays at the right of the title from 640px and goes under it on phones.
5. "…" → "Edit" turns the row into the same form, filled in; Cancel or Save returns focus to "…".
6. "…" → "Add subtask" opens a form under the task; the subtask's estimate never changes the task's estimate.
7. "…" → "Delete" asks once, naming the task and how many subtasks go with it; there is no undo.

## Decisions that shape it

- A list of rows, not cards or a board; one surface, rows divided by a line (R02.1, A01.2).
- The description shows only when the row is open; row actions are in "…" (Luki 6, R02.1, P2).
- The title is the row's one disclosure; the arrow from 640px is decorative (decision J1).
- An estimate is "1 200–1 500 zł"; both amounts or neither; "No estimate" when empty (R07, tokens rule 5, F11).
- A change shows at once and rolls back with a message where it happened, never a toast (spec E01, P4).
