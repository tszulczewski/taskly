# Sign-in (prerequisite)

Every Taskly screen is for a signed-in owner, so sign-in comes before E01. Spec: `.ai/specs/2026-10-16-sign-in-pages.md` (draft, Phase A for the pages). The pages are designed here; they are not in the app yet.

## Flow

1. A signed-out visitor opens any page and is sent to `/sign-in` (server guard).
2. They type their email and password (the eye button shows the password) and press "Sign in"; the button shows "Signing in…" and cannot be pressed twice until the server answers.
3. Wrong credentials: "Email or password is incorrect." above the form (`role="alert"`); what they typed stays.
4. Signed in: always the list at `/`, inside the app shell (name, theme switch, "Sign out").
5. Sign-up is closed unless the server enables it: `/sign-up` then says "Sign-up is closed. Ask the owner of this Taskly." with a link to sign in. When open, the form asks for a name, an email and a password ("At least 10 characters") and signs the account in at once.
6. "Sign out" in the header ends the session and returns to `/sign-in`; if it fails, the header says "Could not sign out. Try again."

## Components

`AuthCard`, `SignInForm`, `SignUpForm`, `SignUpClosed` (`src/product/sign-in/`); `AppShell`, `AppHeader`, `ThemeToggle` (`src/product/shell/`); built on `FormField`, `Input`, `PasswordInput`, `Button`, `Alert`, `Link`, `RadioGroup`.

## Decisions that shape it

- One centred card is the only centred layout in Taskly (What to avoid).
- The theme switch has two named positions, Dark and Light, dark by default, and sets `data-theme` on `<html>` (Q1, Luki 2, P4).
- Validation on leaving a field and on submit; the error under the field; the form error above the form (sign-in spec, Patterns / Form).
- No bottom navigation on phones in version 1 (decision E1); a "Sign in" link on the sign-up page (decision E11).
