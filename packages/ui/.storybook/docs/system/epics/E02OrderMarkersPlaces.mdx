# E02 Order, markers and places

Backlog E02 (#12): E02-S01 reorder tasks and keep the order (#17), E02-S02 mark a task or subtask important and/or urgent (#18), E02-S03 assign a task or subtask to several places (#19). Spec: `.ai/specs/implemented/2026-11-03-order-markers-and-spaces.md` (implemented: markers (#18, Phase 1), places (#19, Phase 2) and reorder (#17, Phase 3)). The design decisions below (G1–G6, H1–H10, POSTEP.md) inform its UI/UX. Screen S7.

## Flow

1. **Reorder from 640px:** drag a task by its handle, or focus the handle and use Space, the arrows and Space (Escape cancels); each step is announced.
2. **Reorder on a phone:** hold the row for 250 ms and drag, or "…" → "Move up" / "Move down". A subtask moves only among its task's subtasks. Completed and unsaved rows cannot be moved.
3. **Markers:** "…" → "Important" or "Urgent" (each a checkbox item); the words appear on the row's second line.
4. **Places:** "…" → "Places…" opens a small popover anchored to "…": tick one or more places, or type a new one and press "Create" (it is ticked for this task at once). The owner starts with eight predefined places (Salon, Sypialnia, Łazienka, Kuchnia, Garaż, Ogródek, Strych, Biuro); a new place gets the next of the ten colours from the app, repeating from the eleventh, and the owner can change it in "Edit places"; at most 20 places (D26).
5. **Edit places** in the same popover: rename, change the colour, or delete (asked in place: "It is removed from every task.").
6. A refused change goes back, with "Could not move “X”. It is back where it was." or "Could not save “X”. It is back as it was." in the row.

## Components

`DragHandle`, `Markers` (`src/product/tasks/`); `PlaceTag`, `PlacePicker`, `PlaceColorPicker` (`src/product/places/`); built on `Menu` (`MenuCheckboxItem`), `Popover` (`PopoverAnchor`), `Checkbox`, `RadioGroup`, `Input`, `Button`.

## Decisions that shape it

- Only the moved row changes its position; the server keeps fractional `position` (AGENTS.md).
- No handle below 640px; long press (250 ms, 5 px) or Move up / Move down (G2, H1).
- Markers and places live in "…", not as icons in the row (G3, A01.3).
- A place is an 8px dot and its name in neutral text, never a coloured pill (R02.3, Q3); colour is never the only signal (WCAG 1.4.1).
- A lifted row has the raised surface, no shadow and no scaling (H8).

## Remaining product work

- Markers (#18, Phase 1) are implemented: "Important" and "Urgent" in the row menu, each its own `PATCH` key, shown at once and put back with "Could not save “X”. It is back as it was." when refused.
- Places (#19, Phase 2) are implemented: each user's eight predefined places on first use, ticking in "Places…" shown at once, create-and-tick, rename, recolour and delete patched onto the rows, the limit of 20, and the loading and load-failed states in the picker.
- Reorder (#17, Phase 3) is implemented: drag by the handle, a long press, the keyboard and "Move up / Move down" for tasks and for subtasks within their task, shown at once, saved with only the new neighbours, and put back with "Could not move “X”. It is back where it was." when refused; completed rows do not move, and the whole list pauses reordering while a quick add is saving.
- Places are one set per user; only a list owner's places can be assigned to its tasks (E02 Q3, decided).
- In the app: the reorder call sends only `afterId` and `beforeId`; markers and places are optimistic with rollback.
