# What is missing

What the design system covers today, what it leaves out on purpose, and what still has to happen outside it. Read this before adding a component: if it is listed under "Not built on purpose", it needs the product owner's decision first (see [Contributing](?path=/docs/design-system-contributing--docs)).

## Not built on purpose

Version 1 has no screen that needs these. Each would need a decision before it is added (decision P4).

| Component                   | Why not                                                                   | Use instead                                                                     | Source             |
| --------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------ |
| Avatar                      | One user, no sharing in version 1.                                        | nothing                                                                         | N02, R02.8, P4     |
| Tabs                        | One screen; two views of the same data are not in scope.                  | separate pages                                                                  | R01.6, P02, P4     |
| Toast                       | Errors stay where they happened; success is the result itself.            | the error in the field, form, row or line                                       | spec E01, P4       |
| Status badge                | There are no statuses; markers are plain words, pills are a generic look. | `Markers`, strike-through for completed                                         | Luki 4, A02, P4    |
| Select                      | No screen chooses one of many.                                            | `RadioGroup` for 2–5 visible options                                            | P4                 |
| Switch                      | No setting applies at once; the theme has two named positions.            | `ThemeToggle` (segmented radio group), `Checkbox`                               | P4, Luki 2         |
| General-purpose dialog      | Details and forms open in the row; dialogs only confirm.                  | `Collapsible` in the row, `ConfirmDialog`                                       | Q2, A01.3, A03, P4 |
| List with filters           | Filters are not in scope; the list is short and ordered by hand.          | `TaskList`                                                                      | P03, P4            |
| Bottom navigation on phones | Version 1 has one screen; a bar with one item does nothing.               | nothing; it comes back with a second screen                                     | P07, decision E1   |
| Date and time formats       | Version 1 shows no dates.                                                 | the formats in [Content](?path=/docs/design-system-content--docs) (decision L2) | L2                 |

## Later (version 2, backlog E04)

Not designed, and nothing here should look ready for them (R02.8, P03): real cost and payments (D17); incurred expenses and the expenses of completed tasks, a single value (D18); marking which job comes before which (D10, Q12); effort (D05); AI estimates (D04, D11); the quick shopping list on the phone; sharing, roles and testing by friends (D02, N02). When one of them starts, it needs its own tokens check (a second total, a new status), and the items above (Avatar, Toast, Tabs) may come back. The quick shopping list is the exception: its parts are ready as recipes, its screen is not (see E04 Later).
